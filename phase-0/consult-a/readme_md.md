# Phase 0 — Consult (แบบ A): Control Catalog ข้ามมาตรฐาน

## ภาพรวม
ฐานข้อมูลกลางโครงสร้าง JSON (`catalog.json`) สำหรับรวบรวม Control จากมาตรฐาน **ISO/IEC 27001:2022 Annex A** (ครบทั้ง 93 ข้อ), **ISO/IEC 42001:2023 Annex A** และมาตราที่เกี่ยวข้องของ **พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA)** พร้อมตารางความเชื่อมโยงข้ามมาตรฐาน (Cross-mapping) การตรวจสอบความถูกต้องของข้อมูลด้วย Pydantic และสคริปต์ค้นหาความสัมพันธ์ระหว่างมาตรฐาน

## โครงสร้างไฟล์
```text
phase-0/consult-a/
├── catalog.json          # ฐานข้อมูล Control ของ ISO 27001, ISO 42001, PDPA และตาราง Mapping
├── schemas.py            # โมเดล Pydantic สำหรับตรวจสอบโครงสร้างและชนิดข้อมูลของ Catalog
├── search_catalog.py     # สคริปต์ตรวจสอบความถูกต้องและค้นหา Control ข้ามมาตรฐาน
└── README.md
```

## การติดตั้งและวิธีรันใช้งาน
```bash
# ติดตั้งไลบรารีที่จำเป็น
pip install pydantic

# 1. ตรวจสอบความถูกต้องของโครงสร้างและจำนวน Control ใน catalog.json
python search_catalog.py --validate catalog.json

# 2. ค้นหาความเชื่อมโยงข้ามมาตรฐานจากรหัส Control
python search_catalog.py --control iso27001:5.34
```

## โครงสร้างมาตรฐานและการจัดหมวดหมู่
1. **การระบุเวอร์ชันและลิขสิทธิ์:**
   - ระบุเวอร์ชันของมาตรฐานทุกฉบับชัดเจน (`ISO/IEC 27001:2022`, `ISO/IEC 42001:2023`, `PDPA B.E. 2562`)
   - ใช้เฉพาะรหัส (ID) และชื่อ Control ทางการ ร่วมกับคำอธิบายสรุป (`description`) ที่เรียบเรียงขึ้นเองเพื่อไม่ละเมิดลิขสิทธิ์เนื้อหามาตรฐาน
2. **การจัดหมวดหมู่ Theme ของ ISO/IEC 27001:2022 Annex A (ครบ 93 ข้อ):**
   - `5.1` – `5.37` (37 ข้อ) $\rightarrow$ `Organizational`
   - `6.1` – `6.8` (8 ข้อ) $\rightarrow$ `People`
   - `7.1` – `7.14` (14 ข้อ) $\rightarrow$ `Physical`
   - `8.1` – `8.34` (34 ข้อ) $\rightarrow$ `Technological`
   *(หมายเหตุ: รหัส `id` ทั้งหมดเก็บเป็น `str` เพื่อป้องกันรหัสอย่าง `"5.10"` ถูกแปลงเป็นตัวเลขทศนิยม `5.1`)*

## รูปแบบโครงสร้าง (`catalog.json`)
```json
{
  "versions": {
    "iso27001": "2022",
    "iso42001": "2023",
    "pdpa": "B.E. 2562"
  },
  "iso27001": [
    {
      "id": "5.1",
      "theme": "Organizational",
      "name": "Policies for information security",
      "description": "จัดทำ อนุมัติ เผยแพร่ และทบทวนนโยบายความมั่นคงปลอดภัยสารสนเทศอย่างสม่ำเสมอ"
    },
    {
      "id": "5.34",
      "theme": "Organizational",
      "name": "Privacy and protection of PII",
      "description": "ระบุและปฏิบัติตามข้อกำหนดด้านความเป็นส่วนตัวและการคุ้มครองข้อมูลส่วนบุคคล"
    }
  ],
  "iso42001": [
    {
      "id": "A.2.2",
      "name": "AI policy",
      "description": "กำหนดนโยบายระดับองค์กรสำหรับการพัฒนาและใช้งานระบบ AI อย่างมีความรับผิดชอบ"
    }
  ],
  "mappings": [
    {
      "from": "iso27001:5.34",
      "to": "pdpa:37",
      "reason": "กำหนดมาตรการรักษาความมั่นคงปลอดภัยของข้อมูลส่วนบุคคลให้สอดคล้องกับหน้าที่ของผู้ควบคุมข้อมูลตามกฎหมาย PDPA"
    }
  ]
}
```

## เกณฑ์การตรวจสอบความถูกต้อง
- รายการใน `iso27001` มีครบทั้ง 93 รหัส ไม่ซ้ำกัน และจัดกลุ่ม `theme` ตรงตามเลขนำหน้าทุกข้อ
- ทุก Control มี `id` (ชนิด `str`), `name` และ `description` ครบถ้วนไม่เป็นค่าว่าง
- มีส่วนข้อมูลของ `iso42001` และมีรายการเชื่อมโยงใน `mappings` อย่างน้อย 10 คู่ พร้อมระบุ `reason` อธิบายเหตุผลกำกับทุกคู่
